# SoftMax 版本 ncu 性能分析

GPU: NVIDIA GeForce RTX 5070 Ti (sm_120 / CC 12.0), 峰值带宽 ~896 GB/s
工具: ncu 2026.3.1, M=N=4096 (每张量 64 MB, 读 64MB + 写 64MB = 128MB 强制访存)

## 实测数据 (ncu, 单次 launch)

| 版本 | 说明 | block | 时间(us) | DRAM字节(MB) | DRAM%peak | SM%peak | L2读sector | 指令数 |
|------|------|-------|---------|--------------|-----------|---------|-----------|--------|
| V1 | block/行 + shared 规约 | 256 | 178.05 | 133.54 | 83.79% | 25.23% | 5,545,240 | 31.1M |
| V2 | warp shuffle 规约 | 256 | 169.76 | 128.90 | 84.85% | 22.67% | 5,509,456 | 26.7M |
| V3 | + float4 向量化 | 256 | 167.65 | 128.02 | 85.33% | 17.30% | 5,629,636 | 20.2M |
| V4 | shared 暂存 exp | 1024 | 163.10 | 125.94 | 86.27% | 35.11% | 2,097,412 | 39.7M |
| V5 | 寄存器缓存 + 单遍访存 | 1024 | 158.75 | 122.09 | 85.92% | 45.48% | 2,097,152 | 50.0M |
| V55| 寄存器缓存(循环/div 版) | 1024 | 174.85 | 131.60 | 84.10% | 35.33% | 2,098,384 | 43.0M |

实际 DRAM 带宽: V1 750 / V2 759 / V3 764 / V4 772 / V5 769 / V55 753 GB/s

## 结论

1. **瓶颈是 DRAM 带宽**。所有版本 dram__throughput 都达到峰值的 84~86%，
   而 SM 吞吐只有 17~45%。典型的 memory-bound，算力完全空闲。

2. **DRAM 流量在所有版本里几乎相同**，都是 ~122~134 MB ≈ 强制的 128MB(读一次+写一次)。
   - V1~V3 逻辑上把 x 读了 3 遍，但 L2 读 sector 高达 ~5.5M (≈2.75×)，
     说明重复读被 L2 挡住了(每个 block 只处理 16KB 的一行，天然驻留 L2)，
     真正落到 DRAM 的仍然只有约 1 遍，所以 DRAM 字节没有暴涨。

3. **V4/V5 的优化去掉了 L2/SM 侧的多余工作**(L2 读 sector 从 5.5M 降到 2.1M，
   指令数也下降)，但 DRAM 字节只从 128MB 降到 122MB(~5%)。
   既然瓶颈是 DRAM，这点流量下降就只能换来 ~5% 的时间提升(167us → 159us)。

4. 因此 **V2→V5 提升很小是必然的**：早期版本的"多读"根本没花 DRAM 带宽的钱，
   后期版本能省的也只有那一点点，早已撞到带宽墙。

## 想再提速的唯一方向

降低 DRAM 流量到 128MB 以下 —— 即减少对全局内存的读写次数：
- 融合进上下游算子(避免把 softmax 输入/输出整体落地)；
- 原地(in-place)计算，省掉一次 64MB 写；
- 半精度/量化，把每元素字节数减半；
- 利用数据的可压缩性(实测流量已低于 128MB，说明有压缩收益)。

单纯在 kernel 内继续做寄存器/L2 优化已无空间。
